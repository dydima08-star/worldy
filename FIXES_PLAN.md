# План: 4 критических фикса (данные + экономика) — ФИНАЛ

## Контекст

Игра Wordle Duo (2 игрока, Firebase RTDB, статика на GitHub Pages) готовится к публикации.
Перед публикацией нужно закрыть 4 бага корректности данных и экономики: мёртвый экран
статистики, бесконечные монеты в майнере, обход суточного лимита рулетки очисткой
localStorage и «товары-призраки» в магазине. Вторая половина работ (PWA, замена
alert/prompt/confirm, уведомления о сопернике, адаптивность, достижения/стрики/история
матчей) — отдельным планом, здесь не проектируется.

**Решения заказчика (внесены в план):** В1 — серверное время делаем сейчас, пятым коммитом,
через утилиту `getNow()` с fallback на локальное время; В2 — `week_pos1` убрать;
В3 — `day_blitz_hunt` удалить; В4 — `week_giant_hunter` ×2 только к очкам; В5 — историю
при сбросе сезона не чистить; В6 — открытую БД принимаем как есть, правила закрываются
руками перед публикацией (раздел 11).

## 0. Где реально лежат данные (результат расследования)

  score/{1,2}              число      очки                 game-logic.js:187, bonus.js:108, shop.js:175
  coins/{1,2}              число      монеты               shop.js:154/176, miner.js, gifts.js:40-41

**В localStorage лежит всего 3 вещи** (все клиентские, ни одна не синхронизируется):

| ключ | где | что защищает | обходится очисткой? |
|---|---|---|---|
| `wordle_role` | [state.js:9](js/state.js#L9), [ui.js:10](js/ui.js#L10) | выбор роли | да, но это не эксплойт |

## 1. Б1 — статистика всегда 0 побед

**Механика.** [stats.js:43](js/stats.js#L43) и [stats.js:54](js/stats.js#L54) считают победу так:

```js
const lastAttempt = w.attempts[w.attempts.length - 1];
return lastAttempt && Array.isArray(lastAttempt) && lastAttempt.every(tile => tile.state === 'correct');
```

— ждут массив объектов-плиток. А пишутся попытки строками:
[game-logic.js:131](js/game-logic.js#L131) `attempts.push(guess)`,
[game-logic.js:191/204](js/game-logic.js#L191) — тот же массив строк в БД. Раскраска плиток
нигде не хранится, она пересчитывается при отрисовке
([game-render.js:43-48](js/game-render.js#L43-L48)). Значит `Array.isArray(строка) === false`
→ побед всегда 0, поражений = всем играм, winRate 0%, гистограмма пустая.

**Формат хранения менять НЕ надо.** Массив строк — правильный и достаточный формат, из него
восстанавливается вся раскраска; он же используется в `isSolved`, `renderBoard`, `isGameOver`.
Миграция формата попыток не требуется. Правильная проверка победы уже есть в коде и её надо
переиспользовать: `isSolved(w)` в [game-logic.js:20-23](js/game-logic.js#L20-L23).

**Вторая половина бага, без которой «прошлые игры» не появятся.**
[words.js:16-28](js/words.js#L16-L28) при каждом рендере меню **удаляет из БД** слова с чужой
датой:

```js
let isOldSystem = w.id?.startsWith('daily_') && !w.id.includes(todayISO);
let isOldPlayer = w.date && w.date !== todayISO;
if (isOldSystem || isOldPlayer) db.ref(`wordle_season_v1/words/${key}`).remove();
```

История живёт ровно сутки. Даже с исправленной проверкой статистика покажет только
сегодняшние игры, а завтра снова обнулится. Уже удалённые игры восстановить невозможно —
их физически нет в БД. Поэтому фикс из двух частей:

1. починить подсчёт (через `isSolved`);
2. завести узел `wordle_season_v1/history/{роль}/{wordId}`, который чистка не трогает:
   писать запись в момент завершения слова и читать статистику из него (со слиянием
   с сегодняшними `words`).

Пункт 2 — это и есть «миграция»: при загрузке один раз переносим все существующие `words`
со `status === 'completed'` в `history` (идемпотентно, по ключу `wordId`). После первого
запуска статистика сразу покажет всё, что ещё живо в БД, и дальше перестанет терять.
Прогресс (rp/score/coins/inventory/miner) не трогается.

Формат записи:

```js
history/{роль}/{wordId} = { len, attempts: attempts.length, win: true|false, date: 'YYYY-MM-DD', author }
```

**История НЕ чистится при сбросе сезона** (решение В5): статистика за всё время.

## 2. Б2 — бесконечные монеты в майнере

**Механика.** [miner.js:195-217](js/miner.js#L195-L217):

```js
const startTime = minerData.cycleStartTime || now;
const elapsed = now - startTime;
const accumulated = Math.floor((elapsed / 3600000) * coinsPerHour);
db.ref().update({ coins: myCoins + accumulated, accumulatedCoins: 0, lastCollectTime: now });
```

Начисление считается от `cycleStartTime`, а сдвигается только `lastCollectTime`, который
**в расчёте не участвует**. `accumulatedCoins` обнуляется, но тоже нигде не читается.
Каждое нажатие «Забрать» выплачивает весь elapsed с начала цикла заново. 10 нажатий =
10 выплат. При батарее 7 уровня (24ч работы) — неограниченная эмиссия.

**Фикс.** База начисления — `max(cycleStartTime, lastCollectTime)`, конец периода ограничен
концом рабочей фазы, после выплаты `lastCollectTime` сдвигается. Та же база в `renderMiner`,
чтобы «Накоплено» показывало только несобранное.

**Поиск таких же таймерных эксплойтов — результат:**

| механика | считает от | двигает точку отсчёта? | вердикт |
|---|---|---|---|
| `collectMinerCoins` [miner.js:195](js/miner.js#L195) | `cycleStartTime` | нет | **БАГ Б2** |
| `renderMiner` «Накоплено» [miner.js:57-58](js/miner.js#L57-L58) | `cycleStartTime` | — (показ) | косметически врёт, чиним заодно |
| смена цикла [miner.js:71-77](js/miner.js#L71-L77) | — | `cycleStartTime = now` | ок, но не сбрасывает `lastCollectTime` — дописать |
| апгрейд батареи [miner.js:270-276](js/miner.js#L270-L276) | — | `cycleStartTime = now` | то же — дописать |
| рулетка [bonus.js:11/104](js/bonus.js#L11) | дата в localStorage | — | **БАГ Б3** |
| страховка комбо [game-logic.js:173](js/game-logic.js#L173) | дата в localStorage | — | **тот же класс, чиним с Б3** |
| буст с рулетки [game-logic.js:162](js/game-logic.js#L162) | `boosts.until` в БД | — | ок (закрывается Шагом 0) |
| срок daily/weekly [shop.js:110](js/shop.js#L110) | `until` в БД | — | ок (закрывается Шагом 0) |
| лимит 7 слов в день [main.js:18-19](js/main.js#L18-L19) | `date` в БД | — | ок |
| сброс сезона [main.js:94](js/main.js#L94) | `seasonInfo.lastReset` в БД | да | ок |

Повторных нажатий боится только майнер — второго такого эксплойта нет.

## 3. Б3 — рулетка обходится очисткой localStorage

**Механика.** Дата спина пишется в `localStorage.last_spin_date_${myRole}`
([bonus.js:104](js/bonus.js#L104)) и читается оттуда же ([bonus.js:11](js/bonus.js#L11)).
Очистка хранилища, инкогнито, другой браузер или устройство → кнопка снова активна, и
`spinDailyBonus` начисляет очки/буст в БД без проверок. Плюс `spinDailyBonus` вообще не
перепроверяет дату — полагается только на `disabled` кнопки.

**Что переносим в БД:**

| localStorage | решение | куда |
|---|---|---|
| `last_spin_date_${myRole}` | **перенести в БД** | `wordle_season_v1/lastSpin/{роль}` = `'YYYY-MM-DD'` |
| `combo_shield_${myRole}` | **перенести в БД** | `wordle_season_v1/comboShield/{роль}` = `'YYYY-MM-DD'` |
| `wordle_role` | оставить | это выбор устройства, не ограничение |

Плюс проверку даты продублировать **внутри** `spinDailyBonus`, а не только в
`openDailyBonus` — иначе спин запускается прямым вызовом из консоли.

**Политика по накопленным монетам: ничего не отзываем**, просто закрываем дыру.
Никаких пересчётов балансов.

## 6. Миграция данных: старые сохранения не теряются

- **Формат попыток не меняется** — массив строк как был. Конвертации нет, риск нулевой.
- **История**: новый узел `history/*`, пишется поверх, ничего не перезаписывает. Разовая
  миграция при загрузке переносит все ещё живые `completed`-слова. Игры, удалённые чисткой
  в предыдущие дни, **восстановить нельзя** — их нет в БД. После фикса статистика покажет
  всё, что есть на момент внедрения, и дальше уже не потеряет.
- **Майнер**: `lastCollectTime` уже есть у существующих игроков (пишется при покупке и сборе);
  `Math.max(cycleStartTime, lastCollectTime || 0)` корректен и при отсутствии поля.
  Балансы не пересчитываются.
- **Рулетка/страховка**: `lastSpin`/`comboShield` в БД пока нет → в первый день после
  внедрения каждый игрок получит один спин и одну страховку. Приемлемо.
- **Серверное время**: при недоступности БД `__serverOffset` = 0 → поведение ровно как
  сейчас. Офлайн майнер и рулетка не ломаются.
- **Магазин**: удаление `day_blitz_hunt` из `SHOP_ITEMS` не удаляет запись из `inventory`
  игрока — она просто перестанет отображаться (`renderShop`/`renderOwned` идут
  от `SHOP_ITEMS`, а не от инвентаря).
- **Монеты, добытые через баги, не отзываются.**
