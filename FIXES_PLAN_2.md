## 1. Текущее состояние по направлениям

### Н1 — удержание и «человечность»

**Завершение партии** пишется в одном месте — `js/game-logic.js:195-211`, пакетом
`db.ref().update({...})`: `rp/{role}`, `score/{role}`, `coins/{role}`, `combos/{role}`,
`words/{id}/status='completed'`, `words/{id}/attempts`, и
**`history/{target}/{id} = {len, attempts, win, date, author}`**. Плюс опционально
`comboShield/{role}`.

Даты в истории есть (`date`, ISO `YYYY-MM-DD`) — этого достаточно для дневных стриков.
**Времени начала/длительности партии нет нигде** — ни поля, ни переменной; `startWord()`
(`js/game-logic.js:92`) время не фиксирует. Нет и `ts` (момента завершения), поэтому
«победы подряд» упорядочить точнее чем по дню сейчас нельзя.

**Слова живут сутки**: `js/words.js:16-28` удаляет из `words/` всё с чужой датой.
`history` не чистится — она и есть единственный долговременный источник для истории
матчей, стриков и достижений.

**Экраны/меню**: 6 экранов (`.screen`) — menu, shop, create, game, stats, miner
(`js/dom.js:8-14`), переключение `showScreen()`. Модалок 5: role, result, exchange,
bonus, gift. Главное меню — 6 кнопок + блок «Доступные слова» (`index.html:43-63`).
Места под достижения/стрики/историю нет — нужен новый экран.

**Имена игроков** зашиты текстом в 8 местах: `index.html:25`, `index.html:33` (шапка),
`index.html:154`, `index.html:157` (кнопки статистики), `js/words.js:36`,
`js/game-logic.js:105`, `js/stats.js:142`, `js/gifts.js:33` и `js/gifts.js:44`.
Ни имени, ни аватара в БД нет.

### Н2 — обратная связь о сопернике

Подписка ровно одна: `gameRef.on('value')` (`js/main.js:102`) — весь корень
`wordle_season_v1` приходит целиком на любое изменение. Значит **новых подписок не нужно
вообще**: достаточно сравнивать предыдущий снапшот с новым.

События, видимые в снапшоте:
- `words/{id}` появился с `target === myRole`, `status === 'pending'` → мне загадали слово;
- `history/{opponent}/{id}` появился с `author === myRole` → соперник доиграл моё слово;
- `words/{id}.attempts.length` вырос, где `author === myRole` → соперник сделал ход;
- `coins/{myRole}` вырос без моего действия → подарок (ненадёжно, поэтому вводим узел `gifts/`);
- `combos/{opponent}`, `achievements/{opponent}`, `rp` соперника — «социальные» события.

### Н3 — PWA

С CDN грузятся ровно два файла: `firebase-app.js` и `firebase-database.js` 8.10.1 с
`www.gstatic.com` (`index.html:8-9`). Шрифты системные (`'Segoe UI', sans-serif`), карт и
иконок нет. Остальной код локальный: `css/styles.css` + 19 файлов `js/` (тяжёлый только
`words-data.js`, ~2255 строк). Нет `manifest.json`, `sw.js`, папки иконок, meta
`theme-color`, `apple-mobile-web-app-*`.

Особенности GitHub Pages: сайт живёт в подпапке `/<repo>/`, поэтому **все пути в манифесте
и регистрации SW — относительные** (`./`), иначе scope уедет в корень домена и SW не встанет.

### Н4 — диалоги

**21 нативный диалог**: 2 × `prompt`, 1 × `confirm`, 18 × `alert`. Полный список — §2.Н4.

### Н5 — адаптивность

Размер плитки считается в **JS**: `js/game-render.js:37-38`

```js
const size = len > 7 ? '34px' : (len > 5 ? '42px' : '48px');
const fs   = len > 7 ? '1.1rem' : (len > 5 ? '1.4rem' : '1.4rem');
```

и применяется инлайном на каждую плитку (`js/game-render.js:52`). Ширина сетки от экрана
не зависит. На 360px: `body` даёт padding 12px с каждой стороны → 336px полезной ширины;
8 плиток × 34px + 7 гэпов × 5px = 307px — формально влезает, но без запаса, а при зуме
строка уезжает; на 320px уже переполнение. CSS-часть сетки — `css/styles.css:154-158`,
`grid-template-columns` ставится из JS (`js/game-render.js:27`).

## 2. Проектные решения

### Н1. Имена, аватары, история, стрики, достижения

#### 2.1 Имена и аватары игроков

**Хранение**: новый узел `players/{роль} = { name: "Аня", avatar: "🦊" }`.

**Ввод**: расширяем модалку выбора роли (`index.html:205-211`) — после клика
«Я — Игрок 1» показываем шаг 2: поле имени (максимум 16 символов) + сетка из
**12 фиксированных эмодзи-аватаров** (решение В15): `🦊 🐻 🐼 🐸 🐙 🦉 🐺 🦁 🐧 🐬 🦄 🐲`.
Кнопка «Готово» пишет `players/{роль}`. Кнопка «Позже» → работает fallback.

**Смена**: в главном меню кнопка «👤 Профиль» открывает ту же модалку в режиме
редактирования (роль не меняется).

**Единая точка чтения** — новые функции в `js/ui.js`:

```js
function playerName(role) { return globalState?.players?.[role]?.name || ('Игрок ' + role); }
function playerAvatar(role) { return globalState?.players?.[role]?.avatar || (role === 1 ? '🔵' : '🟣'); }
```

Все 8 мест из §1.Н1 переводятся на них. Строки в HTML (шапка, кнопки статистики) получают
`id` и заполняются в `renderUI()`. `author === 'Система'` рендерится как «Система 📅».

#### 2.2 История матчей

Новый экран `screen-history` (кнопка «📜 История матчей» в главном меню). Источник —
`history/{myRole}` + `history/{opponent}` (переключатель «Мои партии / Партии соперника»,
как в статистике).

Карточка партии: `🟩/🟥 · СЛОВО (5) · от Ани 🦊 · 4/6 попыток · 12 сен · 1м 47с`.
Все записи в `history` завершённые по определению — утечки секретов нет. Самого слова в
`history` сейчас нет → добавляем поле `word` (старые записи покажут `—`).

Список: **50 записей + кнопка «Показать ещё»** (решение В12), сортировка по `ts`
(новые сверху), фильтр-чипы: **«Всё время / Этот сезон / 7 дней»**.

Новые поля записи `history/{target}/{id}` (только добавление):
`word` (строка), `ts` (мс, `getNow()` на момент завершения), `ms` (длительность партии,
если известна).

#### 2.3 Стрики

Считаются на клиенте из `history/{myRole}`, в БД ничего не хранится:

- **🔥 Серия дней** — число подряд идущих календарных дней (по `date`) вплоть до
  сегодня/вчера, в которых есть хотя бы одна запись с `author === 'Система'` (слово дня).
  Если последняя дата старше вчерашней — серия 0. Показ: в шапке рядом с комбо и на
  экране истории.
- **🏆 Серия побед** — сколько последних записей подряд (по `ts` убыв.) имеют
  `win === true`. Записи без `ts` (старые) сортируются по `date` и уходят в конец —
  серия по ним не строится.
- **Рекорды** `maxDayStreak` / `maxWinStreak` считаются на лету из той же истории.

принимаем). Проверка — функция `checkAchievements()` в новом `js/achievements.js`,
вызывается **только для своей роли** после: завершения партии, покупки в магазине, сбора
монет майнера, обмена очков, отправки подарка. Пишет только новые `id` одним `update`.

|---|---|---|
| `first_win` | Первая кровь | 1 победа (history) |
| `games_10` | Разминка | 10 партий (history) |
| `games_50` | Завсегдатай | 50 партий |
| `games_200` | Ветеран | 200 партий |
| `wins_25` | Четвертак | 25 побед |
| `wins_100` | Сотня | 100 побед |

| `clutch` | На флажке | победа на последней доступной попытке |
| `giant` | Гигантомания | победа на слове из 8 букв (`len === 8`) |
| `blitz` | Блиц | победа быстрее 60 с (`ms < 60000`) |

**Ретроактивная выдача (решение В10)**: при первом прогоне `checkAchievements()` выдаёт
всё уже заслуженное **молча** — тосты подавляются флагом первого прогона (в БД признак не

**Достижения соперника (решение В11)**: видны. Тост при появлении нового ключа в
`achievements/{opponent}` + серая полка соперника на экране истории (переключатель
«Мои / Соперника» общий с историей матчей).

UI: секция «🏅 Достижения» на экране истории — сетка иконок, полученные цветные с датой,
неполученные серые с условием. Никаких модалок «поздравляем» кроме тоста.

#### 2.5 Посезонная разбивка статистики

**Отдельная сущность не нужна.** Сезон = календарный месяц (`js/main.js:105`,
`lastReset = "YYYY-M"`), а в `history` уже есть `date`. Поэтому:

- на экране статистики добавляем чипы **«Всё время / Этот сезон»** — фильтр
  `date.slice(0,7) === текущий месяц`;
- ничего не пишем и не мигрируем; `RP`/`combos` по-прежнему обнуляются сбросом сезона,
  `history` — нет.

Отдельный узел `seasons/` не заводим: лишняя сущность и риск рассинхрона.

#### 2.6 Возврат `day_blitz_hunt` (решение В8)

Таймер: в `startWord()` ставим `sessionStartTs = getNow()` (переменная в `js/state.js`,
в БД не пишем — партия играется в одну сессию). В `submitAttempt()` при завершении считаем
`ms = getNow() - sessionStartTs`, кладём в запись `history` и показываем в модалке
результата («⏱ 1м 47с»). Если игрок перезагрузил страницу посреди партии —
`sessionStartTs` пуст, `ms` не пишем, блиц не засчитывается (честно и без эксплойта).

Товар: `{ id:'day_blitz_hunt', type:'daily', price: 500,
desc:'24 часа: +150 🪙 за победу быстрее 60 секунд (до 3 раз в сутки).' }`.

**Суточный лимит — в БД, как остальные суточные лимиты** (не `localStorage`):
узел `lastBlitz/{роль} = { date: "YYYY-MM-DD", count: 0..3 }`, проверка через `getToday()`
на серверном времени — тот же приём, что уже применён для `comboShield` и `lastSpin`.

> Примечание исполнителю: заказчик описал узел как `lastBlitz/{роль} = дата`; поскольку
> лимит не «раз в сутки», а «3 раза в сутки», в узле рядом с датой обязателен счётчик
> `count`. Имя узла — `lastBlitz`, как просил заказчик. Если `date !== getToday()` —
> считаем `count = 0` и перезаписываем дату.

Экономика: 500 🪙 в сутки против максимум 450 🪙 выплат — товар почти безубыточен для игры
и остаётся челленджем, а не источником инфляции. Это единственное место, где монеты падают
не из обмена; поясняем это в `desc`, чтобы не спорило с текстом модалки результата
(`js/game-logic.js:219`).

#### 2.7 Возврат `week_pos1` (решение В7)

Цена **3000 🪙 / 7 дней**. Обоснование: `perm_pos1` стоит 60000 — при цене 3000 недельный
вариант окупает постоянный за 20 недель, то есть не убивает перм-линейку, но даёт цель
среднему игроку (недельные товары сейчас 300–3400; 3000 — вершина диапазона, и это самый
сильный недельный эффект).

Правила совместимости:

- в `computeStartEffects` условие становится `if (A('perm_pos1') || A('week_pos1')) addIdx(0);`
- в магазине карточка `week_pos1` **скрывается**, если активен `perm_pos1`
  (`isActiveById('perm_pos1')`) — иначе игрок платит за то, что у него уже есть.

### Н2. Уведомления о сопернике

**Механизм — «дифф снапшотов», без новых подписок.** В `js/main.js` заводим
`let prevSnap = null;`. В существующем `gameRef.on('value')` перед `renderUI(data)`
вызываем `diffAndNotify(prevSnap, data)`, затем `prevSnap = snapshotDigest(data)`.
`snapshotDigest` — компактный слепок только нужного (не глубокая копия всего):

```js
function snapshotDigest(d) {
  return {
    words: Object.fromEntries(Object.entries(d.words||{}).map(([id,w]) =>
      [id, { t:w.target, a:w.author, s:w.status, n:(w.attempts||[]).length, len:w.len }])),
    hist:  Object.fromEntries([1,2].map(r => [r, Object.keys(d.history?.[r]||{})])),
    gifts: Object.keys(d.gifts?.[myRole]||{}),
    ach:   Object.keys(d.achievements?.[myRole===1?2:1]||{})
  };
}
```

Первый снапшот тостов не даёт (`prevSnap === null` → только запоминаем), иначе при каждом
заходе посыплется вся история.

| Событие (условие диффа) | Текст тоста |
|---|---|
| Новый `words/{id}`, `target === myRole`, `status === 'pending'` | 🎯 Аня загадала вам слово из 6 букв |
| `words/{id}.attempts` вырос, `author === myRole` | ✍️ Аня сделала ход по вашему слову (3/6) |
| Новый `history/{opp}/{id}`, `author === myRole`, `win` | 🎉 Аня отгадала ваше слово ЛОДКА за 4 попытки |
| То же, `!win` | 😈 Аня не смогла отгадать ЛОДКА |
| Новый `gifts/{myRole}/{k}` | 🎁 Аня подарила вам 50 🪙 |
| Новый ключ в `achievements/{opp}` | 🏅 Аня получила достижение «Снайпер» |
| `rp/{opp}` обогнал `rp/{myRole}` (переход через границу) | 👑 Аня вышла вперёд: 12 400 RP против ваших 12 100 |
| Своё завершение партии + новое достижение | 🏅 Достижение разблокировано: «Блиц» |

**Показ**: тост-контейнер снизу по центру, максимум 3 одновременно, автозакрытие 4 с,
клик — закрыть. Стек, а не очередь: 5 событий подряд не блокируют экран.

**Бейдж во вкладке**: при `document.hidden` копим счётчик и ставим
`document.title = '(3) Wordle Duo'`; на `visibilitychange` возвращаем `Wordle Duo`.
Плюс дублируем счётчик значком на блоке «🎯 Доступные слова» в меню.

**Узел подарков** (нужен и для тоста, и для достижения `generous`):
`gifts/{кому}/{pushId} = { from: 1|2, amount: 50, ts }`. Пишется вместе с переводом монет
в `js/gifts.js:39-42` одним `update` — формат `coins` не меняется.

**Web Push (FCM) — не делаем (решение В14)**: требует `firebase-messaging.js`,
отдельного `firebase-messaging-sw.js`, VAPID-ключа, серверной отправки (Cloud Functions →
план Blaze) и разрешения на нотификации; для игры на двоих выигрыш не покрывает сложность.

**Этап Э8 не начинаем до появления файлов** — Android откажет в установке без 192 и 512.

**Стратегия кэша:**

- `const CACHE = 'wordle-v1';` — версия поднимается вручную в каждом коммите, меняющем шелл;
- **precache (install)**: `./`, `index.html`, `css/styles.css`, все файлы `js/`,
  `manifest.json`, 5 иконок;
- **firebase с gstatic**: кэшируем в `install` через
  `fetch(url).catch(() => fetch(url, {mode:'no-cors'}))` + `cache.put` — opaque-ответ не
  валит весь `addAll`; при неудаче установка всё равно завершается (`Promise.allSettled`);
- **навигация** (`request.mode === 'navigate'`): network-first → при ошибке
  `caches.match('index.html')`;
- **статика** (свой origin + gstatic): cache-first + фоновое обновление
  (stale-while-revalidate);
- **не кэшировать никогда**: запросы к `*.firebaseio.com` и `*.googleapis.com` — сразу
  `return;` без `respondWith`; WebSocket через SW и так не проходит;
- `activate`: удалить все кэши, кроме текущего `CACHE`, + `clients.claim()`.

**Обновление**: без `skipWaiting()` по умолчанию; при `registration.waiting` показываем
тост «🔄 Доступно обновление · Обновить», по клику `waiting.postMessage('SKIP_WAITING')`
→ в SW `self.skipWaiting()` → `controllerchange` → `location.reload()`. Игрока не
выбрасывает посреди партии.

**Оффлайн-деградация (обязательное требование)**: сейчас без сети `gameRef.on('value')` не
сработает ни разу → `globalState === null` → пустое меню. Решение — зеркало снапшота:

- в конце обработчика `on('value')` пишем
  `localStorage.setItem('wordle_snapshot_v1', JSON.stringify(data))`;
- на старте, если через 1500 мс события не было, читаем зеркало, ставим `globalState` и
  рендерим с плашкой «⚠️ Оффлайн — данные от 12 сен, 18:40»;
- записи уходят в очередь RTDB SDK и улетают при появлении сети (в пределах сессии); при
  перезагрузке без сети несохранённое теряется — честно пишем это в плашке.

Тосты и модалки сети не требуют: весь код локальный.

### Н5. Адаптивные плитки

Убираем px из JS, считаем размер в CSS от ширины контейнера и длины слова.

**JS** (`js/game-render.js:27,37-38,52`):

```js
grid.style.setProperty('--cols', len);
grid.style.gridTemplateColumns = '';   // задаётся в CSS
// строки с size/fs и tile.style.width/height/fontSize — удалить
```

**CSS** (`css/styles.css`, взамен строк 154-155):

```css
.grid {
  --gap: 5px;
  --tile-max: 52px;
  --field: min(100vw - 24px, 500px);          /* 24px = padding body 12+12 */
  --tile: min(var(--tile-max),
               (var(--field) - (var(--cols) - 1) * var(--gap)) / var(--cols));
  display: grid; gap: var(--gap); justify-content: center;
  grid-template-columns: repeat(var(--cols), var(--tile));
  margin-bottom: 15px;
}
.tile { width: var(--tile); height: var(--tile); font-size: calc(var(--tile) * 0.5); }
```

Проверка по режимам при ширине экрана 360px (`--field` = 336):

| букв | размер плитки | ширина строки |
|---|---|---|
| 4 | 52px (упёрлось в max) | 223px |
| 5 | 52px | 280px |
| 6 | 51.8px | 336px |
| 7 | 43.0px | 331px |
| 8 | 37.6px | 336px |

При 320px 8 букв дают 33.1px — читаемо. На широком экране поле не растягивается сверх
500px, плитка не превышает 52px. Шрифт масштабируется вместе с плиткой.

Заодно в этом же этапе: `.key { height: clamp(34px, 9.5vw, 42px); }` — на маленьком экране
клавиатура не съедает высоту, на большом кнопки не микроскопические.

## 4. Миграции и совместимость

- **Все новые узлы читаются через `?.` с дефолтом** — на пустой БД и на текущих
  сохранениях UI работает: `players` → «Игрок 1/2», `achievements` → пустая полка,
  `gifts` → пусто, `lastBlitz` → блиц доступен.
- **`history`**: старые записи без `word`/`ts`/`ms` валидны. В списке у них `—` вместо
  слова и дата вместо времени; в серии побед они не участвуют. **Обратной миграции нет и
  быть не может**: слово из `words/` уже удалено суточной чисткой. В шапке списка пишем:
  «Партии до <дата релиза> показаны без загаданного слова».
- **Достижения ретроактивны и выдаются молча** (решение В10): ветеран сразу видит
  заполненную полку, тостов при этом нет.
- **`day_blitz_hunt`/`week_pos1`**: оставшиеся в `inventory` записи прошлых версий снова
  начнут работать штатно (`until` в прошлом → просто неактивно), порчи данных нет.
- **Формат `coins/rp/score/combos/inventory/miner/words` не меняется.** Ни одно
  существующее поле не переименовано и не удалено.
- **Сброс сезона** (`js/main.js:118-134`) не трогаем: `history`, `achievements`, `players`
  переживают смену месяца.
- **PWA**: у игрока, открывшего сайт до появления SW, ничего не ломается — SW ставится при
  следующем визите. `localStorage['wordle_role']`, `wordle_pin_ok` и `wordle_snapshot_v1`
  живут отдельно от кэша SW.

## 9. Перед публикацией (руками, вне кода)

- **Правила RTDB** (перенос из плана №1, всё ещё открыто): закрыть запись в чужую роль.
  С новыми узлами список путей расширяется — `players/{роль}`, `achievements/{роль}`,
  `lastBlitz/{роль}` пишет **только владелец роли**; `gifts/{кому}` пишет **другая** роль
  (нужна отдельная, более мягкая ветка: только добавление новых записей, без правки
  существующих).
- **ПИН в открытом коде** (`js/auth.js:5`) и **ключи Firebase** (`js/firebase.js:9-18`)
  лежат в публичном репозитории. Для RTDB `apiKey` не секрет — секретом являются правила;
  ПИН — фикция. Оставляем осознанно: **реальную защиту дают только правила БД**.
- **HTTPS обязателен для service worker** — GitHub Pages его даёт; локально проверять через
  `http://localhost`, не `file://` (по `file://` SW не регистрируется, `pwa.js` молча
  пропускает регистрацию, игра работает).
- После первого деплоя проверить, что у уже игравших не залипла старая версия: тост
  обновления появляется только со второго визита после релиза.
